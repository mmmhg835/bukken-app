## これは何か

中古マンションの購入検討を、写真・価格推移・相場分析・家計シミュレーションまで
一つで完結させるアプリ。ビルドツールなしの素の ES モジュールで、
ブラウザから GitHub Contents API を直接叩いてデータを読み書きする。サーバーは無い。

| | |
|---|---|
| 現在の版 | アプリ v60 / データスキーマ v19 |
| 規模 | JS 約7,400行・28モジュール |
| 画面 | 一覧 / 比較 / 分析 / ライフプラン / 内見 / 地図 / 設定。ライフプランは ライフプラン・返済負担比率・金利と価格・グラフ・売却 の5サブタブ、内見は チェックポイント・内見の記録・指値 の3サブタブ。一覧の配下に 建物詳細・部屋詳細・取り込み |
| デザイン | 新デザイン（既定）とクラシックを設定で切替。`skin-v2.css` に新案を隔離 |

## 守ってほしいこと

1. **ビルドツールやフレームワークを導入しない**（React / Vite / TypeScript への移行は提案のみ。勝手に実行しない）
2. **派生値を `properties.json` に保存しない**。坪単価・ローン返済額・販売期間は都度計算する
3. **建物と部屋の区別を崩さない**。別の部屋でも同じ値になる項目は建物側
4. **検討状態（status）と募集状況（listingStatus）を統合しない**。別の軸
5. **画面に説明文を足さない**。ラベル・列見出しの副題・構造で伝わるようにする
6. **設備は自由記述にしない**。表記ゆれで比較できなくなるので `spec.js` のタグで持つ
7. **アプリ側リポジトリに個人データを置かない**（物件名・価格・画像はすべて data リポジトリ）
8. スキーマを変えるときは `js/migrate.js` に移行を書き、`CURRENT_SCHEMA` を上げる。
   `store.js` の初期データは migrate 経由で作られるので追記は不要
9. **入力のたびに再描画する箇所では `util.js` の `preserveFocus()` を使う**
   （無いと1文字ごとにフォーカスが外れ、続けて入力できない）
9.5 **数値欄に `type="number"` を使わない。`ui.js` の `numberInput()` を使う**
   （`type="number"` は「1.」を value から読み取れず、打った小数点が消える）
10. 条件分岐で子要素を差し替えるときは `replaceChildren` ではなく `util.js` の `mount()`
    （`replaceChildren` は `null` を文字列 "null" として描画してしまう）
11. 指標グリッドは列数を項目数の約数に固定する（`calcgrid-3/4/6`）。半端な空きマスが出るため。
    **項目数が可変の場所では指標グリッドを使わない**（金利の本数ぶん並べたら空きマスが出た）
12. **画面の状態を変えるだけの操作で `store.markDirty()` を呼ばない**。
    表示の切り替えで保存が走り、中身の変わらないコミットが積もる
13. **入力のたびに並び替わる表を作らない**。1文字ごとに行が動いて打てなくなる。
    `viewing-view.js` は入力中だけ直前の並びを保持している
14. **配色の変数を足したら `skin-v2.css` にも定義する**。`app.css` の `:root` だけに
    足すと、新デザイン（暖色）の上にクラシックの寒色が乗る。実際に `--line-2` で起きた
15. **`store.addRoom` / `addBuilding` にも新しい項目の器を足す**。
    初期データは migrate 経由だが、アプリから足した分はそこを通らない

## コミット前に必ず実行する

`smoke.mjs` は**全23画面**を、指値あり・試算金利を上げた状態・絞り込み・
**中身が空の部屋を混ぜた状態**でも描いて確認する。

```bash
node tools/smoke.mjs          # 全モジュールの読み込みと整合性
node tools/verify-loan.mjs    # ローン計算（返済表と突き合わせ）
node tools/verify-parse.mjs   # 貼り付け取り込みの解析
node tools/verify-sale.mjs    # 売却試算（ローン残高を返済表と突き合わせ）
node tools/verify-lifeplan.mjs # 家計の初期値
node tools/serve.mjs 8765     # 画面確認
```

`smoke.mjs` と `verify-loan.mjs` と `verify-parse.mjs` は**失敗すると終了コードを返す**。
`verify-loan.mjs` は以前 常に 0 を返していたため、全項目が ❌ のまま気づかれていなかった。

`smoke.mjs` は必須。ブロック単位の書き換えで**隣の関数を巻き込む事故が5回**起きている。
モジュールを読み込むだけでは中身の未定義参照に気づけないため、
**全画面の描画関数を実際に呼び出して**確認する作りにしてある。
分岐の中は描いてみないと分からないので、`viewing-view.js` と `lifeplan-view.js` は
画面の状態を `viewingUI` / `lifeplanUI` として出し、smoke から作らせている。

公開後に更新が届かないときは `sw.js` の `VERSION` と `util.js` の `APP_VERSION` を
同じ値に上げる（GitHub Pages が `max-age=600` を返すため）。

## 次にやること：物件情報を充実させる

機能と見た目は一通り揃った。**次は入っている情報を厚くする段階**。

### 1. 実データの投入（最優先）

| 入れるもの | 有効になるもの |
|---|---|
| 建物の住所 | 地図・エリア別相場・町名での絞り込み |
| 部屋の登録日 | 販売期間 |
| 価格推移（登録日と値下げ） | 値下げ分析・相場推移・交渉材料 |
| 写真 | 一覧カード・ギャラリー |
| 額面年収の実値 | 返済負担率（返済負担比率タブで入力する） |

指値（`room.offerPrice`）はライフプランタブで入力でき、元値との比較が出る（v38）。
購入・借入だけでなく、生活費を含む毎月の収支と将来の資産まで同じ表に並べ、
グラフには元値の線を破線で重ねる。
**ライフプランタブの中だけで価格に代えて使う。** 一覧・比較・分析の「現在価格」は元値のまま。

### 2. 入力を楽にする仕組み

手入力が続くと埋まらないので、ここを助けるものを作りたい。

**実データの投入は「スクリーンショットを AI に読ませる」運用にしている。**
掲載ページの画面を撮って渡せば、AI が読み取って data リポジトリの
`properties.json` を直接編集・push する。アプリは画像を読めない（サーバーも
API キーも持たない設計なので、画像認識を組み込むと前提が崩れる）。

### 実データ投入の手順（次はこれを続ける）

ユーザーは物件概要と写真をスクリーンショットで渡してくる。AI 側は次の順で処理する。

| # | 誰が | やること |
|---|---|---|
| 1 | ユーザー | 物件概要を送る（スクショ or テキスト） |
| 2 | **AI** | 読み取って建物・部屋として `properties.json` に登録し push |
| 3 | **AI** | `物件/<建物>/<部屋>/` のフォルダを作る |
| 4 | ユーザー | 写真を撮る／保存する（保存先は気にしない） |
| 5 | **AI** | 写真を見て該当フォルダへ**移動**し、中身の分かる名前に変える |
| 6 | **AI** | 建物か部屋かとカテゴリを判断して登録し push |

写真の置き場は **iCloud Drive の `スクショ/物件/`**（ユーザーのスクリーンショット保存先）。
ここは Mac のスクリーンショット保存先に設定されている
（`defaults read com.apple.screencapture location` で確認できる）。

```
スクショ/物件/
├ README.txt          … 運用の説明。ユーザーも読む
├ W_WEST/
│  ├ _建物/            … 外観・エントランス・共用施設（部屋によらず共通）
│  └ 39階/             … 室内・間取り図・眺望
└ …
```

**分けるのは「どの建物のどの部屋か」だけ。** カテゴリ（間取り・眺望・水回り・収納など）は
AI が写真を見て判断するので、ユーザーにファイル名を付けさせない。

**外観・共用部を部屋側に入れない。** 同じ建物の別部屋を登録したときに同じ写真が重複する。

画像の作り方は `js/image.js` の「高画質」と揃える（本体 長辺2560/q88・サムネ 長辺480/q78・
カバー 長辺320 の data URL）。**長辺が2560以下の JPEG は再圧縮しない**（劣化を避ける）。
`sips` だけで作れるので追加の道具は要らない。ただし `sips -Z` は**小さい画像を拡大する**ので、
長辺が上限を超えるときだけリサイズすること。

登録したら、参照している画像が実在するか・JSON から参照されない孤児ファイルが無いかを
必ず確認する。**AI が直接 push した後は、ユーザーにアプリの再読み込みを促す**
（ブラウザが持っている `sha` が古くなり、次の保存で衝突するため）。

住所を入れたら緯度経度も入れておく。国土地理院の住所検索APIはキー不要で Node からも叩ける。

```
https://msearch.gsi.go.jp/address-search/AddressSearch?q=<住所>
→ GeoJSON。coordinates は [経度, 緯度] の順
```

- 掲載ページの貼り付けテキストからの取り込み（`#/import`）… v35 で実装。**ただし下の制限あり**
- 掲載ページの URL を渡して取り込む（ブラウザから直接は CORS で読めないので未着手）
- 過去の募集情報の一括登録（形式はユーザーに確認する）
- 写真の一括アップロードは**作らない**。既存の追加機能で足りるとの判断

#### 貼り付け取り込みの制限（既知・未修正）

対応しているのは次の2つ。

| 形 | 例 |
|---|---|
| タブ区切りの表 | `価格<TAB>1億5,980万円` |
| 見出し：値 | `価格：1億5,980万円` |

**SUUMO の物件概要をコピーした形は読めない。** 項目名と値が別の行に分かれ、
間に「ヒント」（吹き出し）が挟まるため。この形だと価格・専有面積・間取り・
所在階・管理費・修繕積立金・築年月・総戸数・構造をすべて取りこぼし、
住所と交通くらいしか入らない。

```
価格
ヒント
1億6500万円
```

直すなら `js/parse.js` の `pairs()` を**行単位ではなく「列の並び」として読む**形にする
（行をタブでほどいて1本の列にし、見出しに当たったら次の要素を値として取る。
「ヒント」は項目名の目印として使ってから捨てる）。あわせて `parseFee()` が
`2万2500円` を 2 万円と読んでしまうのも直す（正しくは 2.25 万円）。
**ユーザーはスクショ運用で足りているため、優先度は低いと判断して保留にしている。**

### 3. 項目そのものの拡充

必要になったら足す。**足す前に「別の部屋でも同じ値か」で建物と部屋のどちらに置くか決める。**

- 内見チェックリスト（収納の奥行き、コンセント位置、騒音、日当たりなど）
- 周辺施設（スーパー・病院・学校までの距離）
- 管理組合の状況（修繕積立金の値上げ予定、長期修繕計画）
- 売主・仲介会社、内見日、交渉メモ
