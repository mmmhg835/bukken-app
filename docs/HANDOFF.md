## これは何か

中古マンションの購入検討を、写真・価格推移・相場分析・家計シミュレーションまで
一つで完結させるアプリ。ビルドツールなしの素の ES モジュールで、
ブラウザから GitHub Contents API を直接叩いてデータを読み書きする。サーバーは無い。

| | |
|---|---|
| 現在の版 | アプリ v37 / データスキーマ v15 |
| 規模 | JS 約5,900行・24モジュール |
| 画面 | 一覧 / 比較 / 分析 / ライフプラン / 地図 / 設定（ライフプランは ライフプラン・返済負担比率・グラフ の3サブタブ）。一覧の配下に 建物詳細・部屋詳細・取り込み |
| デザイン | 新デザイン（既定）とクラシックを設定で切替。`skin-v2.css` に新案を隔離 |

## 守ってほしいこと

1. **ビルドツールやフレームワークを導入しない**（React / Vite / TypeScript への移行は提案のみ。勝手に実行しない）
2. **派生値を `properties.json` に保存しない**。坪単価・ローン返済額・販売期間は都度計算する
3. **建物と部屋の区別を崩さない**。別の部屋でも同じ値になる項目は建物側
4. **検討状態（status）と募集状況（listingStatus）を統合しない**。別の軸
5. **画面に説明文を足さない**。ラベル・列見出しの副題・構造で伝わるようにする
6. **設備は自由記述にしない**。表記ゆれで比較できなくなるので `spec.js` のタグで持つ
7. **アプリ側リポジトリに個人データを置かない**（物件名・価格・画像はすべて data リポジトリ）
8. スキーマを変えるときは `js/migrate.js` に移行を書き、`CURRENT_SCHEMA` を上げる。
   `store.js` の初期データは migrate 経由で作られるので追記は不要
9. **入力のたびに再描画する箇所では `util.js` の `preserveFocus()` を使う**
   （無いと1文字ごとにフォーカスが外れ、続けて入力できない）
9.5 **数値欄に `type="number"` を使わない。`ui.js` の `numberInput()` を使う**
   （`type="number"` は「1.」を value から読み取れず、打った小数点が消える）
10. 条件分岐で子要素を差し替えるときは `replaceChildren` ではなく `util.js` の `mount()`
    （`replaceChildren` は `null` を文字列 "null" として描画してしまう）
11. 指標グリッドは列数を項目数の約数に固定する（`calcgrid-3/4/6`）。半端な空きマスが出るため

## コミット前に必ず実行する

```bash
node tools/smoke.mjs          # 全モジュールの読み込みと整合性
node tools/verify-loan.mjs    # ローン計算（返済表と突き合わせ）
node tools/verify-parse.mjs   # 貼り付け取り込みの解析
node tools/verify-lifeplan.mjs # 家計の初期値
node tools/serve.mjs 8765     # 画面確認
```

`smoke.mjs` と `verify-loan.mjs` と `verify-parse.mjs` は**失敗すると終了コードを返す**。
`verify-loan.mjs` は以前 常に 0 を返していたため、全項目が ❌ のまま気づかれていなかった。

`smoke.mjs` は必須。ブロック単位の書き換えで**隣の関数を巻き込む事故が4回**起きている。
モジュールを読み込むだけでは中身の未定義参照に気づけないため、
**全10画面の描画関数を実際に呼び出して**確認する作りにしてある。

公開後に更新が届かないときは `sw.js` の `VERSION` と `util.js` の `APP_VERSION` を
同じ値に上げる（GitHub Pages が `max-age=600` を返すため）。

## いまのデータ

建物4棟・部屋6室。**住所・価格推移・写真がほぼ未入力**なので、
地図・エリア別相場・販売期間の分析はまだ動かない。
「新規物件」という中身のない建物が1件残っているので、不要なら削除してよい。

## 次にやること：物件情報を充実させる

機能と見た目は一通り揃った。**次は入っている情報を厚くする段階**。

### 1. 実データの投入（最優先）

| 入れるもの | 有効になるもの |
|---|---|
| 建物の住所 | 地図・エリア別相場・町名での絞り込み |
| 部屋の登録日 | 販売期間 |
| 価格推移（登録日と値下げ） | 値下げ分析・相場推移・交渉材料 |
| 写真 | 一覧カード・ギャラリー |
| 額面年収の実値 | 返済負担率（いまは手取りからの概算が入っている） |

指値（`room.offerPrice`）はライフプランタブで入力でき、元値との比較表が出る（v37）。
**ライフプランタブの中だけで価格に代えて使う。** 一覧・比較・分析の「現在価格」は元値のまま。

### 2. 入力を楽にする仕組み

手入力が続くと埋まらないので、ここを助けるものを作りたい。

- ~~掲載ページの貼り付けテキストから項目を起こす取り込み~~ … v35 で実装（`#/import`）
- 掲載ページの URL を渡して取り込む（ブラウザから直接は CORS で読めないので未着手）
- 過去の募集情報の一括登録（形式はユーザーに確認する）
- 写真の一括アップロードは**作らない**。既存の追加機能で足りるとの判断

### 3. 項目そのものの拡充

必要になったら足す。**足す前に「別の部屋でも同じ値か」で建物と部屋のどちらに置くか決める。**

- 内見チェックリスト（収納の奥行き、コンセント位置、騒音、日当たりなど）
- 周辺施設（スーパー・病院・学校までの距離）
- 管理組合の状況（修繕積立金の値上げ予定、長期修繕計画）
- 売主・仲介会社、内見日、交渉メモ
